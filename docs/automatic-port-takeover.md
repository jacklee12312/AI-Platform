# Debian 修订 8：自动接管安装端口

所选组件在所有固定摘要镜像、主机依赖准备完成后，按组件接管端口。
容器关闭重启策略、停止并改名归档；系统和用户 systemd 服务停用并 mask，
连同 socket 等触发入口记录恢复信息；普通进程通过 pidfd 先 TERM、超时 KILL。
IPv4 与 IPv6 均复查。宿主机网络模式容器按进程 cgroup 识别，不杀 Docker 守护进程。
探针、SSH、网络和设备驱动维持基础系统边界。

旧组件数据与配置由 root 复制到大容量分区的独立 `ai-platform-backups/<任务ID>`，
逐文件校验内容、权限、属主及链接，持久化成功后才移除原目录。
备份与下载缓存、资源暂存分开，普通缓存清理不得删除备份。
不接管符号链接或挂载点数据根目录，不跨越嵌套挂载。
清单和旧容器完整配置可能包含凭据，仅写入 0700 目录中的 0600 私有文件。

新数据库使用空目录及现场提供的凭据初始化。新 Nginx 使用独立的基础配置；
新 etcd 使用新数据目录。旧同名系统单元和 drop-in 均归档。
本任务已提交的容器通过 ID、固定镜像、挂载和认证复核后续装复用。
中断的接管先恢复再重试；认证或部署失败按当前组件恢复，不回滚其他已完成组件。
包管理器对原生主机软件包的依赖安装仍由 Debian 管理，配置与数据恢复不等于系统镜像还原。

平台文件部署前处理旧平台服务、同名容器及配置，管理中心原数据卷先备份隔离。
平台启动前再次接管 17700、17780；模型容器的内部监听端口不作为宿主机端口清理。
已安装的本地导入模型库不在备份隔离或清理范围内。

验证覆盖：资源失败时旧服务不动、IPv4/IPv6 监听者、容器映射与重启策略、
systemd/socket、旧数据隔离、备份损坏拒绝恢复、续装不覆盖新数据，以及实机接管回滚。
空白设备和重启验收需另外记录。

Docker 镜像存储的本地 ID 支持受信任的 config 摘要和平台 manifest 摘要两种，均要求架构与全部文件系统层匹配。ModelDeck 的两处识别代码以独立资源发行 modeldeck-component-runtime-1.2.0-r8-20261016 交付，由原发布密钥签名并约束原始文件摘要；原平台资源和模型、镜像的签名字节保留。安装计划在逐文件校验原资源后应用该签名资源。参考：Moby containerd ImageInspect 实现 https://github.com/moby/moby/blob/master/daemon/containerd/image_inspect.go 。

修订 8 实机验证已自动接管 3306 并完成 MySQL/Redis、Nginx/etcd。ParadeDB 暴露了非 root 镜像的数据目录属主问题；修订 9 在资源准备阶段解析镜像运行 UID/GID，新目录初始化为该用户私有的 0700 目录，续装不递归改变已提交的数据。镜像用户检查使用无网络、只读、禁权限容器，探测后立即删除。ModelDeck 采用新的独立签名资源 modeldeck-component-runtime-1.2.0-r9-20261016，保留修订 8 的原始资源及交付文件。
