# 随包交付的 CIX NPU 运行环境

Debian 修订 7 增加独立资源发行 `cix-noe-runtime-3.1.2-arm64-20261016`。
压缩归档 1,538,020 字节，包含 libnoe 3.1.2 的 Python 3.11 binding、
libnoe.so.3 及 AIPU 后端库。文件来自已通过 dpkg 完整性检查的
cix-noe-umd 3.1.2 和 cix-npu-onnxruntime 1.2.0；来源摘要记录在发行清单中。
清单使用原安装器受信任密钥签名，保留原平台目录、模型与镜像的签名字节。

安装器在检查页面验证签名和归档，在资源准备阶段自动将运行库安装到
`/var/lib/ai-platform-installer/host-runtime/releases/<资源发行ID>`。
目录由 root 管理，容器只读挂载。缺文件自动补齐；已损坏的普通文件
先备份再修复；符号链接或不可信权限会被拒绝。整个过程不需要联网、apt、
pip，也不依赖主机是否安装了 NOE 软件包。

Kokoro 与共享 CV 服务启动前，先检查已有适配或原镜像；兼容时复用。
不兼容时自动使用包内运行库，并实际加载所选 CIX 模型、提交一次 NPU
推理任务、检查返回状态与输出。只有上下文初始化成功不算兼容。
模型服务最后仍需通过原有真实业务接口的验收。

首次只选择加速卡模型时，也预置 Kokoro / CV 的运行库配置，供 ModelDeck
后续补装。有任意 NPU 模型文件时，两个镜像均用它检查真实任务提交；没有
NPU 模型文件时仅检查设备初始化，明确记录推理验收待模型补装后进行。
不会为了检查而下载未选模型，也不会启动未选模型服务。

从修订 6 迁移时，兼容的旧运行库快照继续复用，缺失或不兼容则切换至
包内版本。配置按内容摘要保存；新记录保留旧配置备份，断电后可继续完成
切换，不覆盖人工修改的未知配置。重复续装会重验运行库与推理结果。

这项功能安装的是平台专用用户态运行库。CIX P1 的 NPU 设备节点与内核
驱动仍由厂家系统提供，XH2 驱动前置条件沿用原安装器。实际推理检查会
自动识别原镜像或随包库是否兼容；两者都不能执行时明确报告设备/内核
驱动问题，不将检测失败标记为安装成功。

发布入口：`python tools/release.py npu-runtime --path <校验后的厂商导出目录> --key <原受信任私钥>`。
该命令拒绝覆盖已发布的运行库发行。二进制归档留在外部资源清单中，不提交 Git。
随后照常执行 `release.py test`、`check --online`、`deb --deb-revision 7`。
