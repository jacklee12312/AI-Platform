# AI 平台安装器 Debian 安装包

适用厂家 Debian 12、ARM64、Python 3.11 设备。Debian 包版本 `1.2.0-7` 是安装器 1.2.0 的修订，增加随包 NPU 运行库、自动补齐与兼容性处理；缓存、模型暂存和解压仍放到大容量分区。原平台资源保持不变，NPU 运行库作为独立资源发行签名交付。

1. 在图形桌面用“软件”打开 `.deb`，安装或更新 AI 平台安装器；需要管理员授权。若系统默认用压缩软件打开，请改用“软件”，也可在终端执行 `sudo apt install ./ai-platform-installer_1.2.0-7_arm64.deb`。
2. 安装完成后，从 GNOME“活动 → 显示应用”搜索“AI 平台安装器”。不要再打开普通文件夹中的旧 `.desktop` 文件。
3. 有探针先比较二进制 SHA-256：一致直接复用，不一致先备份再替换程序及服务，保留全部原配置、证书和设备注册信息；替换后验证 MQTT，失败恢复旧版本。没有探针才显示注册表单并强制安装，通过注册和 MQTT 后安装所选组件与模型。安装 `.deb` 本身不会注册探针、启动组件或安装模型。
4. 模型库独立保存。已复制到 `~/AI-Platform-Model-Library` 的库可被发现；也可在向导的本地导入选项里选择模型库根目录。未勾选的模型以后仍可通过 ModelDeck 补装。

Docker 配套五个软件包任一版本不同时自动卸载旧软件包再安装包内版本，切换期间现有容器短暂停止。保留原配置、容器、镜像、数据卷和数据目录，并恢复原来的运行状态；不执行数据清理。配置备份和中断恢复进度保存在安装任务的私有目录。

配套 NOE 3.1.2 用户态运行库已离线打包，缺失自动补齐、损坏先备份再修复。Kokoro / 视觉模型原环境不兼容时自动切换至平台专用运行库，无需现场安装 apt 或 pip 软件包。首次未选择这些模型也会预置运行库配置，供 ModelDeck 后续补装；有模型文件时执行真实 NPU 推理检查，没有模型文件时先检查设备初始化，待补装后再执行真实推理验收。厂家内核驱动、`/dev/aipu` 与 XH2 SDK 前置条件沿用原要求。

缓存与大文件工作目录自动选择安全候选路径中可用空间最大的分区，通常为 `/opt/ai-platform-data/cache` 和 `/opt/ai-platform-data/work/任务标识/`。模型资源暂存和运行时解压也放在该分区；目录选择保存在任务私有的 `storage.json` 中，继续任务不会改换路径。原缓存可在逐文件校验后复用。

新 `.deb` 只更新安装器程序。平台安装任务、已完成阶段、所选模型和凭据保存在 `/var/lib/ai-platform-installer`，不会随应用更新被清空；这些修订的任务版本均为 1.2.0，所以打开后显示“继续安装”。这不等于重新安装整个平台，也不会重新生成已有密钥。

程序与完整基础资源安装到 `/opt/ai-platform-installer/1.2.0/`，标准命令为 `/usr/bin/ai-platform-installer`。来源配置保存在 `${XDG_CONFIG_HOME:-$HOME/.config}/ai-platform-installer/1.2.0/sources.json`，允许普通用户保存本地导入选择。`ai-platform-installer --check` 只校验安装器并准备用户配置，不启动安装。

移除安装器应用执行 `sudo apt remove ai-platform-installer`。这只移除安装器自身文件；不会清除平台、模型库、数据库或用户配置。包管理器不自动运行整个平台的安装和卸载。

包内 `debian-provenance.json` 同时记录 Debian 封装源码提交和原 1.2.0 资源源码提交。完整基础资源仍包含在包内，组件镜像按选择拉取，大模型不重复装入 `.deb`。原 1.2.0 的远端 Qwen3.6 双卡资源缺失限制保持不变，请取消勾选该模型；本地模型库已排除它。
