# 后台入口与预检

Debian 修订 5 已包含 `container_storage.py`，但桌面授权入口的手写后台文件列表没有复制此模块。因此直接从安装目录进行的存储验收能通过，界面的“继续安装”启动私有后台副本后仍会报 `No module named 'container_storage'`。

从修订 6 开始，授权入口根据 `installer-manifest.json` 复制全部已封存的顶层 Python 模块和版本信息，核对复制后的摘要，再生成全新的私有后台目录。未列入清单的文件和旧后台残留文件不会进入新目录。

启动 systemd 任务之前，入口从实际后台副本解析 `engine`、模型验收入口及其本地依赖，包括函数内的延迟导入；使用系统 Python 的隔离模式在独立进程中导入这些模块，不依赖源码目录或 `PYTHONPATH`。结果和文件摘要记录在私有后台目录的 `worker-manifest.json` 中。复制或依赖检查失败时，保留原后台副本并在派发前报告错误。

用于发布验收的 `--preflight-only` 参数经过同一个授权入口、后台复制和 systemd 启动路径，执行基础环境、所选资源和真实磁盘预算检查（含必要的存储迁移），随后暂停。它不会执行探针替换、组件安装、模型安装或翼起办部署。普通界面继续安装不传此参数，仍执行完整流程。

已有任务的维护人员可以管理员身份运行：

```sh
/usr/bin/python3 /opt/ai-platform-installer/1.3.0/bundle/installer/service_entry.py resume \
  --bundle /opt/ai-platform-installer/1.3.0/bundle --preflight-only </dev/null
```

预检结果以本次更新的公共状态中 `status=paused` 且 `worker_preflight_passed=true` 为准。预检通过不能替代空白设备完整安装、真实模型推理、翼起办业务功能和重启验收。
