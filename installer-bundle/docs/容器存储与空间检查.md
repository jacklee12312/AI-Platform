# 容器存储与空间检查

从 v1.3.0 Debian 修订 5 起，安装器在执行探针、组件库、模型和翼起办安装之前，按实际文件系统检查空间。

- 分别识别本机 Docker 数据目录与 containerd 的持久数据目录。启用 containerd 镜像存储时，将镜像预算计入 containerd 分区，另预留 Docker 容器元数据和数据卷空间。
- 汇总所选模型、镜像、缓存、解压工作目录、翼起办应用和业务数据的预算。同一文件系统上的不同路径合并计算。
- 所在分区足够时直接复用；不足时，尝试将受影响的容器存储复制到已选大容量工作分区旁的持久目录 `ai-platform-container-storage`。若工作目录本身为独立挂载点，则在其中使用 `container-storage` 子目录。复制预算包含原数据副本，不能依赖删除原数据腾出空间。
- 目标需要管理员拥有的本机 ext4 或 XFS 文件系统。没有合适空间、目标不受信任、已有冲突挂载配置或 containerd 还被其他系统共享使用时，在修改服务前停止并说明原因。

迁移会先记录容器、镜像、数据卷和运行状态，再停止原容器与运行时。使用系统 `cp` 保留文件属性、硬链接、扩展属性和稀疏文件，逐项核对内容摘要、属主、权限、时间戳及链接关系。无须安装 rsync。

校验通过后通过 systemd 持久绑定挂载保留原来的 Docker、containerd 和数据卷路径。Docker 服务、套接字与 containerd 服务均依赖这些挂载，避免启动时误用旧目录。挂载配置先通过 systemd 解析检查，再验证实际挂载目录与目标为同一目录，随后恢复原容器状态并重新检查真实磁盘空间。

迁移记录位于 `/var/lib/ai-platform-container-storage/migration.json`，仅管理员可读写，与某次安装的暂存目录分开保存。原数据目录留在挂载下面供回退使用；不要在运行期间清理这些目录，也不要删除新的持久存储目录。

复制或校验失败时恢复原服务，继续安装可重新生成尚未启用的副本。启用挂载后中断时，继续安装使用已校验的新目录恢复挂载与原容器；不会再用旧目录覆盖可能已产生新写入的数据。

专项自动测试覆盖空间足够、目标空间不足、Docker 与 containerd 分区不同、无运行时的新设备、复制损坏、复制中断、启用后的恢复及 systemd 路径解析。模拟测试和存储迁移测试不代表完整空白设备模型推理、业务功能或重启验收已通过。
