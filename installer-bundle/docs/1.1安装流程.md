# 安装器 1.1

适用设备为厂家 Debian 12 ARM64、CIX P1 与 Houmo LQ50/XH2 v1.4.0 的单卡或双卡盒子。以全新设备为主，自动复用已有兼容探针，以及版本、挂载、端口和现场凭据都兼容的所选组件。已有模型平台的跨版本升级、迁移和跨版本任务恢复不在本版范围内。

安装顺序固定为：

1. 数据探针：自动识别本机探针并比较二进制 SHA-256；摘要一致直接复用，不启停服务。不一致先备份旧程序、服务和配置，再替换包内程序及服务，保留原配置、证书和设备注册缓存，确认当前进程 MQTT 连接成功后继续；失败自动恢复旧版本。没有探针时必须填写设备注册信息和接入令牌，安装锁定的 1.1.2 二进制及运行库，注册缓存有效且当前进程 MQTT 连接成功后继续。探针本地不提供 `/health`，不能用模型网关的接口验收探针。
2. 组件库：准备模型平台必需的 Docker/Compose，按用户勾选安装 Nginx、etcd、MySQL、Redis、ParadeDB、Neo4j、MinIO、Milvus。选择 Milvus 时自动包含 MinIO 和 etcd。每项检查通过才进入下一项，Milvus 最后启动；没有选择组件时跳过组件库服务安装。
3. 模型平台：复用原有签名资源获取、单卡/双卡模型选择、网关和管理中心部署及真实推理验收；最后复查组件。只有本任务全新安装的探针才开启网关与容器采集并复查连接；复用和替换探针的采集配置保持原状。

任何阶段失败都不会显示安装完成；原有后台任务、断点缓存和暂停/继续机制保留。继续任务会重新识别探针并比较摘要，恢复中断的替换事务；本任务拥有的全新探针继续未完成安装，所选组件重新检查当前状态。不会因关闭向导而结束后台任务。

## 现场设置

探针识别依据是标准二进制 `/usr/local/bin/data-probe`、配置目录 `/etc/data-probe` 和 systemd 的 `data-probe.service`。桌面识别只查看安装标记和服务装载状态，不读取私有令牌、注册缓存或原绑定信息。进入安装设置页以及正式启动前重新识别，管理员后台再独立识别，不能用配置里的复用标记跳过安装。

没有探针时才显示安装表单，必须填写负责人、项目、城市、地点、用途、访问策略、设备型号、平台地址和接入令牌；没有跳过或取消探针的选项。已有探针无需重新填写，摘要不一致会明确提示先备份再替换程序及服务，保留原绑定、证书、注册缓存和采集配置。替换失败自动恢复；私有备份保存在任务的 `private/workflow/probe-replace-*` 目录，权限为 0700，不进入公共报告。若已识别的外部探针随后消失，停止并要求恢复，防止空配置重新注册。

也可先复制 `workflow-settings.example.json` 后导入，其 `probe.mode` 为 `auto`，示例不包含有效令牌或密码。无探针时填写注册字段；有探针时仅需 `"probe": {"mode": "auto"}`。导入旧配置同样以本机实际识别结果为准，已有探针不会因导入其他注册信息而被重新绑定。

在“选择组件与模型”页的“组件库”标签中勾选组件，默认全部不选。Docker/Compose 是模型平台必需环境，单独标为必需。勾选 Milvus 会自动选中并锁定其 MinIO、etcd 依赖；取消 Milvus 后自动依赖一并取消，先前主动勾选的 MinIO 或 etcd 会保留。确认页显示实际安装范围，包括自动包含的依赖。

仅为所选 MySQL、Redis、ParadeDB、Neo4j、MinIO 设置 12–128 字符密码；选中 MinIO 或 Milvus 时再填写 MinIO 用户名。未选组件不要求凭据，也不部署、启动、检查其端口和数据目录或执行健康验收。Redis 启用认证；MinIO 的同一组凭据传入 Milvus。安装器仅在私有请求和配置文件中保存所需凭据，不放入公开诊断报告。连接配置仅包含实际选择的组件与依赖，输出到 `/home/cix/AI-Platform-1.1-connections.json`，属主为安装用户 cix，权限为 0600；完成页可另外导出。

配置文件的 `components.selected` 是主动勾选的组件标识列表，可用值为 `nginx`、`etcd`、`mysql`、`redis`、`paradedb`、`neo4j`、`minio`、`milvus`，空列表表示不选组件。例如只选 MySQL 和 Redis 时填写 `"selected": ["mysql", "redis"]` 并设置它们的密码。仅选 Milvus 时填写 `"selected": ["milvus"]` 及 MinIO 凭据，依赖由后台解析。旧配置不含该字段时保留原有全装含义，导入后会在界面显示全部选中。继续任务保留最初选择，仅允许修改资源来源。

探针的原始文件日志仅保存在 root 可读的 `/var/log/data-probe`。探针控制台输出经过过滤后进入系统日志，注册令牌和密码被替换；仍保留用于判断 MQTT 连接状态的事件。

## 固定版本与离线资源

| 组件 | 版本或镜像 | 主机端口 |
|---|---|---|
| Docker CE | 29.7.2，五个配套 DEB 摘要锁定 | — |
| Nginx | Debian 12 的 1.22.1，具体包修订固定 | 80 |
| etcd | Debian 12 的 3.4.23，具体包修订固定 | 2379、2380 |
| MySQL | mysql:8.0.36 | 3306 |
| Redis | redis:7.4 | 6379 |
| ParadeDB | paradedb/paradedb:0.24.0-pg18 | 5432 |
| Neo4j | neo4j:5.26.29 | 7474、7687 |
| MinIO | dappros/minio:RELEASE.2025-09-07T16-13-09Z | 9000、9001 |
| Milvus | milvusdb/milvus:v2.6.21 | 19530、9091 |

六个镜像都固定 linux/arm64 清单摘要、镜像配置摘要和文件系统层摘要。MinIO 的 ARM64 清单为 `sha256:2f25127f784f002f1b98df5ae40cb1a67e0b8a877c90b6113c14b223a2ac65a5`，来源为第三方原版镜像副本。

1.1.2 起，默认交付包的 `support-files/files/workflow/` 仅包含清除示例注册信息后的探针包和 Debian ARM64 依赖闭包，不再携带六个组件镜像。组件镜像按勾选范围获取，优先复用已校验的本机镜像或本地归档；允许联网时从固定仓库按 ARM64 清单摘要拉取，启动前继续核对配置 ID、架构和全部文件系统层。签名清单保留可选离线归档的大小和 SHA-256，现场仍可通过本地资源目录导入。选择“仅本地”且缺少所选组件镜像时明确报错，不自动联网。

1.1.2 移除民主测评票识别及 Qwen3Guard 内容审核模型，平台保留 25 项模型/服务与 10 个平台镜像。ModelDeck 不再显示审核面板、审核参数或模型审核范围；公共网关移除审核及民主测评接口。Kokoro 运行必需的共享依赖继续保留。平台其他运行时继续随包携带，模型权重仍按所选来源获取。

ParadeDB 数据挂载到 `/var/lib/postgresql`。其余组件数据在 `/data/对应组件名`。已有非空数据库目录但无可兼容容器时会停止，不自动清空或初始化。已有容器使用非配套 Docker 时会停止，不替换其 Docker 环境。安装过程不重写系统 APT 源或 Docker daemon.json。

## 验证边界

本机构建测试、QEMU 下运行 ARM64 MinIO 和 Compose，以及探针加载检查，都属于开发验证。真实平台注册及 MQTT 链路、六组件完整联通、空白单卡和双卡设备上的模型推理、重启后的自启，必须在目标设备上验收并单独记录。候选包不自动视为通过现场验收。
