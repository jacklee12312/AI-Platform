# 安装器 1.1

适用设备为厂家 Debian 12 ARM64、CIX P1 与 Houmo LQ50/XH2 v1.4.0 的单卡或双卡盒子。以全新设备为主，可以明确复用兼容且注册信息一致的探针，以及版本、挂载、端口和现场凭据都兼容的组件。已有 1.0.x 模型平台的升级、迁移和跨版本任务恢复不在本版范围内。

安装顺序固定为：

1. 数据探针：安装锁定的 1.1.2 二进制及运行库，填写设备注册信息和接入令牌；设备注册缓存有效、当前探针进程 MQTT 连接成功、本地健康接口正常后继续。
2. 组件库：配置统一的 Docker/Compose，检查 Nginx、etcd，依次部署和检查 MySQL、Redis、ParadeDB、Neo4j、MinIO、Milvus。每项检查通过才进入下一项，Milvus 最后启动。
3. 模型平台：复用原有签名资源获取、单卡/双卡模型选择、网关和管理中心部署及真实推理验收；最后复查组件和探针，并开启探针的网关与容器采集。

任何阶段失败都不会显示安装完成；原有后台任务、断点缓存和暂停/继续机制保留。继续任务会重新检查探针和组件的当前状态，不仅依赖历史完成标记。不会因关闭向导而结束后台任务。

## 现场设置

在安装设置页填写负责人、项目、城市、地点、用途、访问策略、设备型号、平台地址和接入令牌。也可先复制 `workflow-settings.example.json`，填写完整后导入。示例不包含有效令牌或密码。复用已有探针时勾选复用，并填写与它完全一致的绑定信息；接入令牌可以留空。本版不自动重新绑定其他平台或项目。

分别设置 MySQL、Redis、ParadeDB、Neo4j、MinIO 的 12–128 字符密码及 MinIO 用户名。Redis 启用认证；MinIO 的同一组凭据传入 Milvus。安装器仅在私有请求和配置文件中保存凭据，不放入公开诊断报告。连接配置输出到 `/home/cix/AI-Platform-1.1-connections.json`，属主为安装用户 cix，权限为 0600；完成页可另外导出。

探针的原始文件日志仅保存在 root 可读的 `/var/log/data-probe`。探针控制台输出经过过滤后进入系统日志，注册令牌和密码被替换；仍保留用于判断 MQTT 连接状态的事件。

## 固定版本与离线资源

| 组件 | 版本或镜像 | 主机端口 |
|---|---|---|
| Docker CE | 29.7.2，五个配套 DEB 摘要锁定 | — |
| Nginx | Debian 12 的 1.22.1，具体包修订固定 | 80 |
| etcd | Debian 12 的 3.4.23，具体包修订固定 | 2379、2380 |
| MySQL | mysql:8.0.36 | 3306 |
| Redis | redis:7.4 | 6379 |
| ParadeDB | paradedb/paradedb:0.24.0-pg18 | 5432 |
| Neo4j | neo4j:5.26.29 | 7474、7687 |
| MinIO | dappros/minio:RELEASE.2025-09-07T16-13-09Z | 9000、9001 |
| Milvus | milvusdb/milvus:v2.6.21 | 19530、9091 |

六个镜像都固定 linux/arm64 清单摘要、镜像配置摘要和文件系统层摘要。MinIO 的 ARM64 清单为 `sha256:2f25127f784f002f1b98df5ae40cb1a67e0b8a877c90b6113c14b223a2ac65a5`，来源为第三方原版镜像副本。

新增资源在完整资源包的 `support-files/files/workflow/` 中，包含清除示例注册信息后的探针包、Debian ARM64 依赖闭包和六个 Docker 离线镜像。每个文件的大小和 SHA-256 都在已签名的工作流清单中；本地导入按相同摘要验收。组件镜像缺少本地文件且允许联网时，按固定的 ARM64 清单摘要拉取，实际启动使用已核对的镜像配置 ID。原有完整运行时和平台镜像继续保留，模型权重仍按所选来源获取。

ParadeDB 数据挂载到 `/var/lib/postgresql`。其余组件数据在 `/data/对应组件名`。已有非空数据库目录但无可兼容容器时会停止，不自动清空或初始化。已有容器使用非配套 Docker 时会停止，不替换其 Docker 环境。安装过程不重写系统 APT 源或 Docker daemon.json。

## 验证边界

本机构建测试、QEMU 下运行 ARM64 MinIO 和 Compose，以及探针加载检查，都属于开发验证。真实平台注册及 MQTT 链路、六组件完整联通、空白单卡和双卡设备上的模型推理、重启后的自启，必须在目标设备上验收并单独记录。候选包不自动视为通过现场验收。
